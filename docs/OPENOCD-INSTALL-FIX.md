# Windows OpenOCD 安装目录重命名失败

## 问题与边界

截图显示已解压的 `.openocd-staging-*` 目录发布到摘要目录时出现 `EPERM rename`。现有实现只尝试一次，短暂文件句柄占用也会直接失败；仅凭错误无法确认具体占用进程。没有修改用户 AppData 权限、结束进程或删除用户安装。

## 实现

- 发布目录及回滚旧安装时，对 `EPERM`、`EACCES`、`EBUSY` 进行最多 5 次尝试，总等待约 1.5 秒；其他错误直接返回。
- 目标目录已存在时不重试覆盖，验证并复用其他窗口发布的同一运行时。
- 无用临时目录清理被锁住时，不阻止复用已验证的运行时。
- 持续失败时返回占用/权限提示，保留旧安装及恢复路径。
- 提供独立解压的 OpenOCD 目录供「选择路径」使用，绕过缓存目录发布步骤；仅执行 `--version` 验证，不连接开发板。

## 验证

- 先新增测试，确认旧代码在模拟前两次 `EPERM rename` 时失败。
- 修复后验证短暂占用恢复、持续占用有限失败、旧安装回滚、并发安装复用及清理失败。
- `npm run check`：493 个文件检查通过，0 失败。`npm run quality`：244 个测试文件和格式、类型、覆盖率门槛通过。
- 独立路径中的真实 Windows 程序通过 `--version` 和 `find target/stm32g4x.cfg` 检查，没有初始化探针或连接开发板。
- 实际用户目录中的占用来源尚未确认；若持续拒绝访问，可使用独立路径。
