# 串口监视器和运行时 RAM

在侧栏点击「串口监视器」打开大页面。选择串口、波特率、数据位、校验位和停止位后打开连接。支持 UTF-8 文本和 HEX 收发、换行、定时发送、收发字节计数、清空和将当前缓冲区保存为文本。显示缓冲区最多保留 2 MiB / 2000 条记录，超出时页面显示已丢弃的字节数。关闭页面会停止定时发送并释放串口。串口被其他程序占用时先关闭占用程序。

## 运行时 RAM

编译期 FLASH/RAM 来源于 ELF 和内存配置；运行时 RAM 是单独的指标。运行时数据必须由固件准确统计并提供下面两个保留在 ELF 符号表中的全局变量，均为 4 字节、4 字节对齐的 `volatile uint32_t`：

```c
volatile uint32_t emberprobe_ram_used_bytes = 0;
volatile uint32_t emberprobe_ram_total_bytes = 0;
```

运行时总量可按项目需要设置，已用量必须由项目根据其内存布局、堆和任务栈实际统计并定期更新。插件不推测任意分配器或任务栈的用量。见 [接入示例](examples/emberprobe_ram_metrics.c)：它只提供上报接口，不自行计算使用量。

重新编译并使用与目标固件一致的 ELF。在侧栏「实时读写」点击「开始」，插件复用该采样连接读取变量；退出或停止采样后不显示实时值。未提供变量时显示未接入；总量为零或使用量超过总量时显示数据无效。符号不能被链接器移除，RAM 变量需要位于 ELF 中可写的已分配区域。

Keil 工程优先使用所选 Target 的 `Cpu` 中互不重叠的 `IRAM` / `IROM` 容量，支持起始地址加容量和起止地址两种写法；ELF 区段提供编译占用。布局不明确时只显示字节数，不猜测总容量。自定义内存配置及编译器优化请结合工程链接结果检查。
