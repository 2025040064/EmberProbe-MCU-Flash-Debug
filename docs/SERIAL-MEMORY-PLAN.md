# 串口与内存界面实施计划

## 目标

在现有 Keil 自动导入改动之上，增加串口监视、紫色编译内存进度、固件上报的运行时 RAM，以及更清晰的侧栏布局和字体。保留原有未提交修改。

## 架构

- 串口由扩展宿主中的独立服务管理，Webview 只通过消息执行用户操作；本机依赖随 VSIX 打包。关闭页面时停止定时发送并释放端口。
- 编译内存沿用 ELF 分析，优先读取选中 Keil Target 的有效内存布局，容量未知时不猜测。
- 运行时 RAM 只读取固件提供的 `emberprobe_ram_used_bytes` 和 `emberprobe_ram_total_bytes`，复用已有采样/探针协调；未接入或无效时明确显示状态。
- Keil 导入入口置顶，芯片信息与 MCP / Agent Skills 收入可折叠区域；使用系统字体回退和紫色进度条，保留可访问性与 VS Code 主题兼容。
- 测试覆盖串口生命周期、数据编解码与循环发送、Keil 容量、运行时状态、侧栏交互；执行仓库要求的检查和本地打包。
